# ARTIFACTS.md - перечень артефактов и протоколов проекта Calculator

## 1. Введение

Документ фиксирует полный перечень артефактов проекта «Calculator»
(WPF, .NET Framework 4.7.2) по состоянию после лабораторных работ №1
(реорганизация структуры) и №2 (диаграмма компонентов), а также
описывает протоколы взаимодействия между модулями Views, Services,
Infrastructure и App. Документ адресован участникам команды и
предназначен для быстрого вхождения в проект, настройки окружения на
новой машине и согласования контрактов между модулями при дальнейшей
интеграции и рефакторинге.

## 3. Протоколы взаимодействия

### Протокол: ICalculatorService

- **Участники:** Views → Services.
- **Назначение:** выполнение арифметических и научных операций и разбор пользовательского ввода по нажатию кнопок.
- **Интерфейс:**
  - `string InputDigit(string currentDisplay, string digit)`
  - `string InputComma(string currentDisplay)`
  - `string SetOperation(string currentDisplay, string pressedOp, out string newDisplay)`
  - `string PressEquals(string currentDisplay, out string histLine)`
  - `string PressSci(string currentDisplay, string func, out string histLine)`
  - `string Backspace(string currentDisplay)`
  - `string Negate(string currentDisplay)`
  - `void Clear()`
  - `string FormatNumber(double value)`
- **Формат данных:** текущее значение дисплея передаётся и возвращается как `string` (десятичный разделитель - запятая, как принято в RU-локали); символ операции/цифры - `string`, взятый из `Content` нажатой кнопки.
- **Соглашения:** методы интерфейса именуются как `<Глагол><Существительное>` (InputDigit, SetOperation); обработчики в окнах называются `<Действие>_Click` и напрямую делегируют вызов в `calc`.

### Протокол: IHistoryService

- **Участники:** Services (CalculatorService использует его внутренне) и Views (чтение истории по кнопке «Hist»).
- **Назначение:** сохранение и чтение истории выполненных вычислений.
- **Интерфейс:**
  - `void AppendEntry(string line)`
  - `List<string> LoadHistory()`
  - `void ClearHistory()`
- **Формат данных:** текстовые строки вида `«<выражение> = <результат>»`, дописываются построчно в файл `history.log`; чтение — построчно через `File.ReadAllLines`.
- **Соглашения:** ошибки файлового ввода-вывода подавляются (try/catch) и не прерывают вычисление; история сохраняется между запусками приложения (в отличие от чисто оперативной истории в памяти).

### Протокол: App.ChangeTheme(int)

- **Участники:** Views → App.
- **Назначение:** единая точка доступа окон к смене темы оформления без прямой зависимости от Infrastructure.
- **Интерфейс:** `void ChangeTheme(int themeIndex)`; поля `MainWindowTheme`, `EngWindowTheme` (int, хранят текущую тему каждого окна).
- **Формат данных:** индекс темы - `int` (1, 2 или 3 - три предопределённые цветовые палитры).
- **Соглашения:** Views никогда не обращается к ThemeManager напрямую - только через App.

### Протокол: ThemeManager.ChangeTheme(Application, int)

- **Участники:** App → Infrastructure.
- **Назначение:** применение выбранной палитры к ресурсам приложения.
- **Интерфейс:** `static void ChangeTheme(Application app, int themeIndex)`.
- **Формат данных:** записывает значения `SolidColorBrush` в словарь `app.Resources` по фиксированным ключам (`ColorBg`, `ColorMainText`, `ColorNumBtn` и т.д.); выбор палитры - по `int`-индексу.
- **Соглашения:** ключи ресурсов именуются по шаблону `Color<Назначение>`.

## 4. Соглашения об именовании и версионировании

**Именование:** классы и статические классы - PascalCase (`CalculatorService`, `ThemeManager`); интерфейсы - с префиксом `I` (`ICalculatorService`, `IHistoryService`); методы сервисов - `<Глагол><Существительное>` (`AppendEntry`, `LoadHistory`, `SetOperation`); обработчики событий элементов управления - `<Действие>_Click`, совпадают с именем обработчика в XAML; пространства имён соответствуют каталогам (`Calculator.Views`, `Calculator.Services`, `Calculator.Services.Interfaces`, `Calculator.Infrastructure`).

**Версионирование:** на текущем учебном этапе используется единственная ветка `main`; для сообщений коммитов рекомендуется модель Conventional Commits (например, `docs: add ARTIFACTS.md with project artifacts and protocols`, `refactor: split Calculations into CalculatorService and HistoryService`). Для будущих релизов рекомендовано семантическое версионирование (SemVer, `MAJOR.MINOR.PATCH`) с отметкой релизов тегами Git (`git tag -a vX.Y.Z`).

## 5. Заключение

Проведена инвентаризация всех артефактов проекта «Calculator», артефакты классифицированы по категориям (проектные, исходного кода, конфигурации, сборки, тестовые, вспомогательные); отмечены артефакты, не подлежащие версионированию, и подтверждено их исключение через `.gitignore`. Определены и описаны четыре протокола взаимодействия между модулями (ICalculatorService, IHistoryService, App.ChangeTheme, ThemeManager.ChangeTheme) с указанием интерфейсов, форматов данных и соглашений об именовании. Результаты оформлены в виде настоящего документа ARTIFACTS.md, что подготавливает проект к дальнейшей модульной интеграции и командной разработке.
